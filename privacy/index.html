Privacy and retention

⚠
DRAFT — pending legal review. This is a first honest description written from how the site and services actually work today, not a lawyer-reviewed policy. It will be reviewed before any paid service opens, and it will change. Where it is vague, that is because the thing it describes is not built yet.

Version: first draft, 2026-09-21.

This website

standguard.net collects nothing. It is static files served from a CDN. There is no server, no database, no account system, no login, no analytics, no advertising and no tracking pixel. Nothing you do on these pages is recorded by this project.

Two consequences worth stating plainly:

  • The account check runs in your browser. When you type an account name and press the button, your browser sends that public account name directly to public XPR Network nodes. Those nodes are operated by third parties, and like any web server they can see the request and your IP address. That is the same exposure you have using a block explorer. The result is never sent to us, because there is no us to send it to.
  • The hosting provider sees requests. Cloudflare Pages serves these files and, like any host, handles the network request. Its own logging is governed by its policies, not ours.

Fonts are currently loaded from Google Fonts, which means your browser makes a request to Google when a page loads. Self-hosting those fonts to remove that request is on the planned list.

Service intake, when services open

No service is open, so no intake data exists yet. When one does open, this is what it will involve:

  • What is collected: what you send in order to be helped — your question or brief, the exact public identifiers (accounts, token ids, contracts, transactions, collections, pools), your project links, and any private material you choose to share for a readiness check.
  • Why: solely to perform and deliver the work you asked for.
  • Whether it is stored: yes, in a case workspace, for as long as the job and its revision window are open.
  • Where: operator-controlled storage. The specific infrastructure is not published, because publishing it helps nobody but an attacker.
  • How long: the retention period will be stated here as an exact number before any paid service opens. It is not stated yet, because guessing one now would be a promise nobody has tested.
  • Who can access it: the operator. Not other customers, and not the public.
  • Third-party AI and API providers: yes — research work passes through third-party model and API providers. Assume that anything you send may be processed by one. Do not send anything you would not be willing to have processed that way.
  • Correction and deletion: ask, and it will be corrected or deleted where the work is not already delivered through an external platform that keeps its own record.

Public-chain identifiers

Account names, transactions, token holdings and contract interactions on XPR Network are public by design. Anyone can read them and this site does not change that.

Being public is not the same as being fair game. This project treats them responsibly: no verdict is published about a named natural person, no account is named as a bad actor without a block or a trade behind it, and no report draws a conclusion about who someone is from what an address did.

Evidence delivered through XPR Agents

Where a job is delivered through the XPR Agents platform, part of that job record may be publicly visible according to how the platform works. That visibility is the platform’s behaviour, not a choice made here, and it will be pointed out before you buy anything.

Using your case as a public sample requires your separate, explicit permission and redaction. It is never assumed from a purchase.

What you will never be asked for

A seed phrase, a private key, a recovery phrase, a wallet password, an API secret, or a signing credential. Not by this site, not by Guard.IAN, not in chat, not in an intake form. No page here has a field for one. Anyone asking for one while claiming to be this project is not this project.
