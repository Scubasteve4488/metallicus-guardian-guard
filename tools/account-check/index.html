Account Check

Read the current public state of any XPR Network account, in plain English, with every source and every failure named.

🔒
Nothing is connected and nothing is stored. There is no wallet connection on this page — no signing session, no seed-phrase field, no transaction path. Typing a name sends that public account name to public XPR Network nodes from your own browser, exactly as a block explorer does. standguard.net has no server and no database, so nothing you type reaches us or is kept anywhere.

1–12 characters using a–z, digits 1–5, and “.” only. A leading @ is fine — it will be ignored.

What this tool will not tell you

  • Whether an account is safe. It cannot, and neither can anything else. On-chain state says what an account did, never who controls it or what they intend.
  • Whether a token it holds is legitimate. Anyone can send any token to any account. A symbol appearing in the list is not an endorsement of it — and someone else can put a token in your account without asking you.
  • Its full history. This reads current state. History needs a history node and a different kind of report.
  • Anything off this chain. Other chains, exchange accounts and custodial balances are invisible here.

Why a failed read is shown as a failure

If every node fails, this tool says so. It does not print a zero. The difference matters: “this account has no liquidity positions” and “we could not find out whether this account has liquidity positions” lead to opposite decisions, and a tool that blurs them is worse than no tool.

The same rule covers one specific trap carried over from the previous version of this tool: XPR account names may contain the digits 1–5, so an all-numeric name like 333555 is valid. A table query that passes such a name raw gets read as an integer, returns an empty result with a success code, and the caller then reports “nothing found” as a fact. This tool encodes the name first, so that silent wrong answer cannot happen.
