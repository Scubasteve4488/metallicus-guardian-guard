XPR Agent Diagnostic

Waitlist

You have an agent registration, endpoint, runner or service concept, but you do not know whether public discovery, job readiness, evidence delivery, security boundaries and current official-source alignment are actually correct.

What you supply

  • The agent’s XPR account.
  • Its endpoint.
  • Its public repository, if there is one.
  • Runtime type.
  • Intended capabilities.
  • Current job and service status.
  • Testnet or mainnet status.
  • Permission to inspect public endpoints and repository material.

What you receive

  1. Registry and ownership snapshot.
  2. Agent-card review.
  3. Health-endpoint review.
  4. A2A and public endpoint review.
  5. Service and job readiness review.
  6. Expected-versus-advertised capability comparison.
  7. Source and version lock.
  8. Signing and authority boundary questions.
  9. Security and prompt-injection exposure checklist.
  10. Ranked repair plan.

What is excluded

  • No private-key handling, ever. Do not send one; it will not be accepted.
  • No proof of security from public endpoints alone — a clean public surface is not a secure system.
  • No production deployment.
  • No mainnet action.
  • No code repair unless purchased separately.
  • No guarantee the agent will win jobs.

How it is judged done

  • Public agent identity and endpoint were checked.
  • Health and agent-card behaviour were reproduced.
  • Advertised capabilities were compared with proven behaviour.
  • The official upstream revision is recorded.
  • Every untested claim is identified as such.
  • The first repair step is concrete and bounded.
ℹ
Guard.IAN runs this diagnostic against itself and intends to publish the result in full, including what it fails. That sample is Planned, not written.
